# 江苏省自然资源科研诚信智慧治理平台（React + FastAPI）

面向江苏省自然资源科研管理场景的本地可运行原型：上传本子/政策/文献，做**带原文引用的问答**、**预审→专家审核→终审全过程案卷**和**多年文献趋势分析**。

- 前端：React 19 + TypeScript + Vite + ECharts / ECharts GL（3D 趋势图）
- 后端：FastAPI + Uvicorn + Pydantic（OpenAPI 文档 `/docs`）
- RAG：DOCX/DOC/PDF/OFD/ODT/RTF/PPTX/XLSX/HTML/TXT 解析 + 结构分块 + TF-IDF 检索 + 千问/离线双模式
- 部署：不侵入现有科技管理系统，独立工作台，内网可运行
- 安全：威胁模型、认证/授权/出口门禁/文件防护与部署检查清单见 `SECURITY.md`
- 设计：设计 token、字体/色彩、组件状态、动效与无障碍契约见 `DESIGN.md`

## 2. 登录与角色

系统内置账号密码登录（原型方案）与四类角色；正式部署时替换为厅统一身份认证（SSO/OIDC），角色模型沿用。

**演示账号**（首次启动自动创建，密码统一 `yanxin2026`，仅限内网验证）：

| 账号 | 角色 | 权限 |
|---|---|---|
| `admin` | 管理员 | 全部功能 + 用户管理（`/admin` 创建账号） |
| `manager` | 科研管理 | 上传/删除文档、导入文献与专家、移除演示数据、外部推送 `/api/ingest/*` |
| `reviewer` | 评审专家 | 问答、预审、查重匹配、文献趋势、知识图谱；文档中心只读 |
| `viewer` | 访客/申报账号 | 问答、知识图谱、文献趋势、文档中心与历史课题/材料体检只读；可对归属本人的申报材料发起项目预审与材料查重，不含专家匹配 |

- 演示账号**仅在本机监听（127.0.0.1）时自动创建**；对外监听默认不创建，确需演示设 `SEED_DEMO_USERS=1` 并用 `DEMO_USER_PASSWORD` 指定强密码（留空则生成随机密码打印到日志）；
- 登录后可在“用户管理”页自助改密（`POST /api/auth/password`，改密后所有旧会话失效）；
- 登录成功后显示短暂“正在进入评审工作台”过渡，落地 `/welcome` 欢迎页；刷新与会话恢复不重复播放；
- 登录失败限速：同一用户名+IP 连续失败 5 次（窗口 300 秒）或同一来源 IP 失败 20 次返回 429，可配 `LOGIN_MAX_FAILURES` / `LOGIN_IP_MAX_FAILURES` / `LOGIN_WINDOW_SECONDS`；随机用户名不能绕过 IP 桶，限速分桶键为定长摘要，登录请求体与入参另有长度上限；
- **数据不出内网（代码级强制）**：LLM 端点仅放行回环/内网/内网域名，公网 DashScope/OpenAI 默认阻止（健康检查显示“公网出口已阻止”），确需使用须显式设 `ALLOW_EXTERNAL_LLM=1`；
- 专家库读取（`GET /api/experts`）限评审专家/科研管理/管理员——访客不可见回避关系与负载画像；
- Qwen3 思考模式：`LLM_ENABLE_THINKING` 留空不发送（兼容旧服务）、设 0 显式关闭（避免只返回思考内容）、设 1 开启；
- 解析边界：单文件 128MB；Office 压缩文档限制条目数、单条目体积、解压总量和压缩比，并对 ODT/OFD/PPTX/XLSX 使用统一 `OFFICE_PARSE_TIMEOUT_SECONDS`；PDF 默认只解析前 2000 页（`MAX_PDF_PAGES` 可调，0 为不限），单次本地处理最多执行 `OCR_MAX_PAGES` 次 OCR 且受 `MATERIAL_PROCESS_TIMEOUT_SECONDS` 总时限约束，可主动取消并保留旧正文；RTF 控制字线性解析并受 `RTF_PARSE_TIMEOUT_SECONDS` 限制，旧版 DOC 的多个本机转换器共享 `DOC_PARSE_TIMEOUT_SECONDS` 总预算；XML 会对原始字节和 UTF-16/UTF-32 解码结果同时检查 DTD/实体；HTML 遵循声明字符集并在无声明时严格回退 GB18030，无法确认时标记待核验；上传原件仅属主可读写，断连或解析失败会清理半截文件；HTTPS 部署设 `COOKIE_SECURE=1` 强制会话 Cookie 加密传输；

- 会话：登录后签发 HttpOnly Cookie（7 天有效）；任何接口返回 401 时前端自动回到登录页。
- 权限双层执行：前端按角色隐藏按钮，后端中间件统一拦截 `/api/*` 并对写操作按角色返回 403。
- 材料级权限叠加在角色之上：manager/admin 可核验全库；其余角色仅能读取公开、归属本人、额外授权或本人专家任务所对应的材料，进入路由不等于全库可读。
- 密码以 PBKDF2 加盐哈希存储；`admin` 可在“用户管理”页创建正式账号。

## 3. 快速启动

环境要求：Python 3.10+；PDF 解析需要 `pdftotext`（macOS `brew install poppler`，Ubuntu `apt install poppler-utils`）。旧版 DOC 需要 LibreOffice/antiword；macOS 可使用系统 textutil 或 Quick Look。如果 `frontend/dist` 已存在，运行时不依赖 Node；重新构建前端需要 Node 20+。

```bash
cd "课题申报：科研诚信驱动的自然资源科研全周期智慧治理与大模型协同关键技术研究"

cp .env.example .env        # 可选：填入千问配置
./run.sh                    # 自动选择可用解释器，缺依赖时自动安装
```

打开 <http://127.0.0.1:8010>；接口文档 <http://127.0.0.1:8010/docs>。

依赖由 `run.sh` 在所选解释器上自动安装。如果本机没有可用环境（例如 Homebrew Python 受 PEP 668 限制），先 `python3 -m venv .venv` 再运行 `./run.sh`——它会优先使用项目 `.venv`。

`run.sh` 做的事情：

1. 自动选择解释器（显式 `PYTHON` > 项目 `.venv` > conda/Anaconda 已知路径 > 系统 `python3`，取首个能导入依赖者）并检查依赖；
2. 如果 `frontend/dist` 不存在，执行 `cd frontend && npm install && npm run build`；
3. 用 Uvicorn 启动 FastAPI，并托管 React 构建产物。

数据库可选 SQLite 或 PostgreSQL：

```bash
# 单机测试：使用 data/app.db
DATABASE_BACKEND=sqlite
VECTOR_STORE_BACKEND=numpy

# PostgreSQL + pgvector
DATABASE_BACKEND=postgresql
DATABASE_URL=postgresql:///yanxin_review
VECTOR_STORE_BACKEND=pgvector
PGVECTOR_DIM=1024
```

从现有 SQLite 数据迁移到 PostgreSQL：

```bash
createdb yanxin_review
psql -d yanxin_review -c 'CREATE EXTENSION IF NOT EXISTS vector'
python3 -m tools.migrate_sqlite_to_postgres \
  --sqlite data/app.db \
  --database-url postgresql:///yanxin_review
```

迁移脚本幂等保留主键；目标已有相同主键时保留目标记录，不能用重复迁移覆盖权限配置。`--clear` 仅允许名称以 `_test` 结尾的隔离测试库，生产迁移不清空目标业务表。PostgreSQL 后端首次初始化会创建业务表、`chunk_vectors` 和 pgvector HNSW 索引。

云主机部署、备份恢复、巡检和远程冒烟脚本见 [`deploy/README.md`](deploy/README.md)。部署文件要求运行配置与模型密钥放在 `/etc/yanxin-review/` 的 root-only 环境文件中，不写入源码目录；公开演示只使用合成数据。

首次启动会自动：

1. 创建当前数据库表、`data/uploads/` 与嵌入缓存目录；
2. 演示账号种子（仅本机监听时创建，见“登录与角色”）；课题申请书含个人信息，**默认不再自动入库**——需要示例本子时在 `.env` 显式设 `SEED_SAMPLE_DOC=1` 并把文件放入项目根目录后重启；
3. 写入 42 篇合成演示文献，用于验证趋势功能；
4. 写入 12 位合成演示专家（`is_sample=1`），用于验证专家匹配。

不需要演示数据时，在 `.env` 中设置 `SEED_SAMPLE_DOC=0`、`SEED_DEMO_PAPERS=0`，或在界面中删除示例本子、点击“移除演示文献”；演示专家无环境变量开关、首次启动会无条件写入，可在“查重匹配”页点击“移除演示专家”一键清理。

**政策语料（真实公文）不是演示数据，运行时不联网自取**：`./run.sh` 启动时会自动导入一次（幂等、失败不阻断）；直接用 `uvicorn` 起服务或改了快照后，手动跑一次：

```bash
python3 -m rag.corpus            # 把 corpus/ 下两部公开公文写入文档库（幂等）
python3 -m rag.corpus --list     # 只看清单、来源与入库状态，不写入文档
```

前提是仓库自带的 `corpus/policy/*.txt` 已就位（随仓库提供）。要重新抓取或换机器重抓：

```bash
python3 tools/fetch_corpus.py            # 抓取 → 覆盖 corpus/policy/ 与 corpus/sources.json
python3 tools/fetch_corpus.py --check    # 不联网，只校验快照与清单 sha256 是否一致
```

手动抓取只接受固定政府来源的 HTTPS，校验证书并拒绝重定向；失败时保留原快照和已有清单，不回退 HTTP。当前江苏转载渠道的 HTTPS 证书在本机校验失败，重新抓取会明确报错，随库交付的快照仍可离线使用。SHA256 校验用于发现快照改动，不是政府签名或来源认证；更新后仍需核对发布机关及正文。`rag.corpus --force` 只重建清单中同来源政策，不删除已移出清单的历史政策，避免破坏已有引用。

## 5. 接入大模型

`LLM_PROVIDER` 选供应商，其余变量按需覆盖。预设只填 key 就能用，不用记 base_url 和模型名：

| `LLM_PROVIDER` | 端点 | 默认模型 | 需要的 key |
|---|---|---|---|
| `qwen` | DashScope 兼容模式 | `qwen-plus` | `QWEN_API_KEY` / `DASHSCOPE_API_KEY` |
| `deepseek` | `api.deepseek.com/v1` | `deepseek-flash` | `DEEPSEEK_API_KEY` |
| `openai` | `api.openai.com/v1` | `gpt-4o-mini` | `OPENAI_API_KEY` |
| `custom` | `LLM_BASE_URL`（内网 vLLM / SGLang / Ollama） | `LLM_MODEL` | 可不填，内网通常不校验 |
| `auto`（默认） | 按已有 key 推断，兼容旧配置 | — | — |

DeepSeek 预设仅使用自身密钥或显式 `LLM_API_KEY`，不会回落使用千问密钥。OpenAI 预设默认不发送千问/DeepSeek 思考扩展参数；显式 `LLM_THINKING_STYLE=none` 可覆盖所有预设，其他显式方言同样优先。

```bash
# 千问（留好位置，将来填 key 即用）
LLM_PROVIDER=qwen
QWEN_API_KEY=sk-xxxxxxxx

# DeepSeek
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-xxxxxxxx
ALLOW_EXTERNAL_LLM=1               # 公网端点默认被拦

# 内网自建（推荐用于真实评审材料）
LLM_PROVIDER=custom
LLM_BASE_URL=http://10.0.0.10:8000/v1
LLM_MODEL=Qwen3-32B
```

任何预设都可以用 `LLM_MODEL` / `LLM_BASE_URL` 覆盖。**别用旧的 `QWEN_BASE_URL` 覆盖**：
预设模式下它不参与，就是为了防止留着 A 家的地址却换成 B 家的 key。

两个与模型有关的行为：

- **思考模式**：DeepSeek 默认开思考，预审要 JSON 时思考会把 `max_tokens` 吃光、正文为空。
  代码按 `style` 发不同参数（DeepSeek 发 `thinking.type=disabled`，千问发 `enable_thinking`），
  `LLM_ENABLE_THINKING=0` 可显式关掉，`LLM_THINKING_STYLE` 可强制指定方言。
- **没有模型时的兜底**：问答退化为按关键词与章节挑句的原文摘录，未命中资料时不具备通用世界知识，预审退化为规则引擎（形式完整性、
  诚信表述、字面查重、政策条款提示），趋势退化为规则统计。三者都会在结果里写明「只到这一步」——
  预审报告的 `limitations` 会逐条列出规则做不到的事（语义归纳、版本时效、改写型重复），
  前端显示在结论下方。**这时不会假装做过语义判断。**

顶栏不显示模型配置，智能问答输入区提供模型选择。每条回答与预审报告另存实际生成来源，报告 Markdown 导出同步保留；调用失败显示“已回退离线摘录/规则预审”，中途断线保留已输出内容的模型来源并标为“生成中断”。旧结果缺少来源记录时不推断供应商。

旧 `QWEN_*` 接口继续可用：自动配置识别官方 DeepSeek 与 DashScope 端点后显示对应名称，自建兼容端点保持通用名称；不改变密钥选择或出口授权。

**注意**：公网端点（DashScope / DeepSeek / OpenAI）意味着上传的评审材料会离开内网；真实评审场景请使用内网模型或先完成数据合规审批。

## 7. 当前实现方式

### 问答链路

1. 解析：DOCX 用 Word XML（含脚注/尾注）；DOC 经本机转换器；PDF 用 `pdftotext`；OFD/ODT/PPTX/XLSX 读取容器内 XML；RTF/HTML/文本按可见文字提取，再按段落/章节切分。
2. 分块：按章节标题、段落、句边界切分，块大小约 700 字，重叠 100 字并对齐到句边界；保留页码/章节。
3. 检索：分为 TF-IDF 与向量两层（见下一节），按可用后端自动选择；返回 Top K 片段。
4. 生成：配置千问时，将编号资料 + 问题 + 最近对话发给 Qwen；未配置时使用摘录式回答。
5. 引用：回答中的 `[n]` 与检索片段一一对应；前端右侧面板展示原文和相似度。
6. 通用知识：配置模型且未检索到相关资料时，仍可回答一般知识问题，但必须标注“以下为通用知识回答，未使用项目资料”，且不得生成虚假引用；未配置模型时无法凭空提供通用知识。

文献趋势不是与当前申报书或问答上下文对比。它只在选定的年份窗口内比较文献表的**标题、作者关键词和摘要**：

1. 以字符 2–3-gram TF-IDF 计算查询与每篇文献的余弦相似度；
2. 查询词直接在标题/关键词/摘要出现时增加命中分；
3. 直接命中且分数 ≥0.02，或语义分数达到 `max(0.12, 最高分×0.6)` 才进入相关集合；
4. 最高分不足 0.02 时显示零命中。“零命中”只表示当前导入文献集合没有匹配到该主题，不表示现实中不存在相关研究。

### 检索策略（TF-IDF 与向量）

两套打分并存，对外接口不变：

- **TF-IDF（字符 2–4 gram）**：始终构建。零依赖、可离线，是基线，也是向量不可用时的回落；
- **向量（embedding）**：可用时接管检索。词面不重合也能命中——问“调查取证时禁止哪些手段”，TF-IDF 排第 4，向量排第 1。

后端由 `EMBED_BACKEND` 选择：`local`（进程内 sentence-transformers，模型放 `models/`，不进仓库）、`api`（OpenAI 兼容 `/embeddings`，默认 `BAAI/bge-m3`）、`none`（纯 TF-IDF）；默认 `auto` 按 本地 → API → none 取第一个可用的。

向量存储由 `VECTOR_STORE_BACKEND` 选择：

- `numpy`：进程内精确点积，适合单机与测试；
- `pgvector`：向量写入 PostgreSQL，使用 HNSW 余弦索引，生产默认；
- `milvus`：通过 `MILVUS_URI` / `MILVUS_TOKEN` 连接独立 Milvus，适合百万级向量和高并发。

三种存储共享 `index / score / clear` 接口。先取 `VECTOR_CANDIDATE_K` 个向量候选，再叠加关键词、章节权重和文档范围过滤；查重仍使用独立的 TF-IDF 字面相似度。

Milvus 与模型端点使用同一出网口径：公网 URI 默认被阻止，必须显式设置 `ALLOW_EXTERNAL_MILVUS=1` 并完成数据出域审批；本地文件 URI 或政务外网地址不触发公网开关。

安全口径与 LLM 一致：公网端点默认拦住，必须显式 `ALLOW_EXTERNAL_EMBED=1` 才放行（本机 `127.0.0.1` 不受限）。**真实评审材料应使用 `local` 或内网端点**，见 `SECURITY.md` §5。

向量按「单条文本 + 模型」哈希缓存在 `data/embed_cache/`：新增一份文档只补算它自己的分块，不会整库重算。实测 32 条冷启动 0.6s（2 次批量请求），命中缓存 0.1ms；单次检索向量 37ms、TF-IDF 0.8ms。

阈值要分开设：TF-IDF 的无关文本余弦接近 0，而向量对无关中文段落也有 0.3–0.4 的底噪。本语料实测——「金星的地质构造」「如何做红烧肉」这类完全无关的问题最高分 0.34–0.44，领域内问题 0.48–0.74——所以：

- 结果下限 `EMBED_MIN_SCORE=0.45`（低于此值不出结果，等于「没有相关资料」，问答会据此说明资料不足）；
- 政策引用下限 `0.58`：写进报告要引条款，要求比普通问答更严；
- 证据面板的相似度条按后端分档映射（向量 `0.45–0.80` 铺满整条，TF-IDF 仍按 `×240`），否则向量分值一律顶到 99%，条形读不出强弱。

同一批 14 个政策问题（答案按原文关键句定位，不靠人工挑）的召回对比，用 `python3 -m tools.eval_retrieval` 可复跑：

| 模式 | 命中@3 | 命中@1 | MRR |
|---|---|---|---|
| TF-IDF | 71.4% | 57.1% | 0.631 |
| 向量 | **92.9%** | **64.3%** | **0.762** |

提升集中在“问法与条文用词不一致”的问题上（如“项目信用管理涵盖哪些环节”“调查取证禁止手段”）；两边都命中的题，向量多数仍排第 1，代价是个别词面强匹配的题（论文代写代投）向量退到第 2。仍有 1 题两种模式都未命中：答案在江苏省办法、但 221 号文的“处理”章节在词面上更近，这是单向量召回的已知短板，后续靠混合检索（词面 + 向量）补。

**政策不进入查重候选池**（在候选截断前排除），仍用于问答和预审政策引用。

**查重不走向量。** `similarity_between_docs()` 固定用 TF-IDF：查重要看的是字面重合，向量会把“主题相近但没有重复”判成高相似，反而制造误报。

### 项目预审

规范性检查采用独立固定规则 `precheck-v1`，满分100分，按材料20、任务路线20、指标20、预算15、诚信10、复用15分组织21个子项。它衡量材料表述与可核验程度，不评价科研价值；权重和60/80分界为试行口径，尚未经专家标注校准。详细算法和适用边界见 [预审计分标准](docs/预审计分标准.md)。

报告 `scoring` 保存版本、`earned`（已确认得分）、`pending_points`（待核验分值）、`upper_bound`、六维分项与证据。不能可靠核验的项保持待核验；区间为已确认得分至最高可能得分，不把未知当通过。目前附件6分、目标任务对应6分、任务方法对应6分和任务经费对应3分须人工核验，因此满分100不表示系统能自动确认最终100分。此版记录待核验状态，尚无人工确认后写回计分的工作流。

初始分档为低风险≥80、中风险≥60、高风险<60；仅当区间上下界处于同档时定档，跨档显示“待核验”。关键章节未识别及可可靠核算的预算冲突单独提示，可使风险标为高，不以其他得分抵消。正文不足1500字只提示解析/内容长度边界，不单凭长度认定高风险。分档与得分均不构成立项、资助或处罚结论。

模型模式保留系统检索生成的「文件＋章＋条」政策引用、可展开原文、人工核对提示和真实查重结果；模型不能覆盖这些证据，也不能改变规则分、待核验状态或风险分档。

- 规则检查：章节完整性、科研诚信/数据安全/伦理/知识产权表述、参考文献、文档长度。
- 文本查重：段落级 TF-IDF 提供候选与相似片段；另对最多5份候选的保守保留可能重叠的分块正文计算连续24个有效字符一致区间的并集覆盖，不用最高余弦代替覆盖率。它不是全库全文重复率，未排除模板和合理引用；有命中时复用覆盖10分及引用/模板核对3分待核验，没有可用候选或索引未就绪也待核验。相似 ≠ 抄袭，必须人工判断。
- 政策引用：检索已入库政策文件中的相关条款作为提示；随库公开政策可通过 `run.sh` 自动导入，引用内容与适用性须人工核对。
- 千问配置后，由模型生成结构化 JSON 预审意见；解析失败自动回退到规则预审。
- 只输出可复算的规范性规则分和待核验区间，不输出项目排名、科研价值评分或立项结论；报告页脚带免责声明。历史报告未记录计分时显示“未记录”，不重算历史归档。

### 历史沿革 / 文献趋势

1. 用主题词在文献库中做相关性筛选（标题/关键词/摘要命中 + TF-IDF）。
2. 按年份统计发文量和主题词出现次数。
3. 生成 3D 年度发文量柱状图、3D 主题热度矩阵；可切 2D 折线/柱状图。
4. 生成主题热度、年度高频主题、代表性文献和趋势摘要；配置千问后由模型生成 3–5 条趋势研判。代表性文献可直接进入文档中心的“文献数据”视图并定位对应条目。

具备阅读权时，问答引用、查重命中、预审政策/查重依据及卷宗当前/历史材料的名称可直接打开对应文档正文。无权读取的查重来源只显示匿名代号、本材料片段及相似度，不显示对方题名、片段或原文链接。

案卷归档即使正文已包含完整证据，仍保留获准阅读的原文链接；补充区域不重复同一段证据。无权读取的依据由后端裁剪；受限阅读副本与签名原件区分，不改写已签名归档。

### 动效规范

- 字体三层分工：品牌、印章与 KPI 数字用宋体；页面、面板、区段、报告、文档和步骤标题用加粗黑体；回答、研判和证据原文等长正文用楷体（多平台回退）；文案块统一 `letter-spacing .02em`、行高 1.8+；
- 统一缓动 `cubic-bezier(.22, 1, .36, 1)`；页面进入 220ms、退出 100ms，按钮反馈 150ms；
- 入场位移不超过 10px，hover 抬升 1–2px，避免大幅缩放/旋转；
- 导航使用共享布局滑块；3D/2D 切换交叉淡入，避免图表硬切；
- 换主题时 KPI 数值滚动/字符串淡入、趋势摘要与年度主题重新入场、文献卡片错峰、图表数据过渡；
- 3D 自动旋转速度 2，可手动暂停/继续；拖拽结束静置 4s 后恢复，离屏、后台与减少动态效果下暂停；
- 侧边栏收起/展开用可取消的 rAF 补间（220ms 缓出，只动 transform）；图表在容器尺寸变化时即时 resize，避免多重补间；
- 分析请求做 280ms 防抖：快速响应不闪 loading 遮罩，慢请求才显示“分析中…”；按钮不使用持续旋转图标；
- 每次分析 KPI 四张卡整体重新入场，年份跨度等不变值也有反馈；
- 支持 `prefers-reduced-motion`：关闭自动旋转、CSS 动画与 Framer 位移动画；
- 登录页采用与工作区一致的主题顶栏和居中账号表单，背景有低对比缓慢柔光；不使用鼠标视差，减少动态效果时停用；
- 状态变化动效（Framer `AnimatePresence`）：表格行删除退出、匹配面板空↔结果切换、上传弹窗文件芯片切换、KPI 数值变化 480ms 闪光；
- 登录成功过渡：深色印章 + 扫描线约 280ms（reduced-motion 即时切换），无假进度数字；仅真实登录触发，刷新不重复；
- 全局尺度：正文 15px、表格 13.5px、标签 12px、控件高 40px、导航侧栏 240px、品牌标题箱 380px（折叠 84px）、主区留白 32–48px；`WorkDeck` 步骤名称桌面 15px、编号 11px，手机与矮屏使用 10.5–11.5px；≤1400px 表格自动紧凑；
- 路由级 code splitting，3D 图表按需加载。

### 交互边界

- 侧边栏可收起为图标栏（状态记忆于本地，窄屏默认收起）；≤680px 改为抽屉导航（遮罩、焦点陷阱、ESC 关闭、路由切换自动收起）；
- 无障碍：全局「跳到主要内容」skip link、路由切换焦点移交主区、图表 `role="img"` 文本摘要；焦点环与辅助文字对比度实测满足 WCAG AA（含深色侧栏与登录页脚）；
- 高度适配：聊天与证据面板按 `100dvh` 收缩并只做面板内滚动；弹窗/预审栏内部滚动；矮屏时登录页收紧间距并保持可滚动；375×560 下上传弹窗按钮仍可达；
- 侧边栏、顶栏、按钮、筛选、KPI、图表工具栏、表格操作不可选中/拖动；
- 正文（问答、证据、摘要、论文信息、表格内容、预审报告）保留选中与复制；
- 导航链接无下划线，禁用原生链接拖拽；
- 固定滚动条槽（`scrollbar-gutter`），顶栏上传按钮不随页面高度/滚动条变化而左右移动；
- 3D 图表仍支持拖拽旋转；滚轮不再缩放图表，而是正常滚动页面。

### 3D 图表实现

- `echarts` 5.x + `echarts-gl` 2.x；
- `bar3D` 年度柱状图：自动旋转、拖拽旋转、光照与阴影；**滚轮缩放已关闭，滚轮用于页面滚动**；
- `bar3D` 主题矩阵：主题 × 年份 × 文献数；
- `postEffect` 开启 Bloom/SSAO，增强立体层次；
- 顶部“3D / 2D”切换；浏览器无 WebGL 时自动使用 2D 并给出提示；
- KPI 数字滚动、卡片入场、报告风险环等使用 Framer Motion / CSS 动画。

`tests/test_robustness.py` 覆盖的加固点：

- **空文献库趋势**：`papers` 为空时返回空趋势而非在 TF-IDF 处崩溃。
- **SPA 路径穿越**：`/../` 等越界路径一律 404，绝不返回 `frontend/dist` 之外的文件。
- **错误信息不外泄**：未捕获异常统一返回“服务器内部错误”，响应体不含内部细节（如密码、堆栈）。
- **`top_k` 边界**：`ToolCheckRequest.top_k` 限定 `1–20`，越界返回 422。
- **SQLite 并发**：连接启用 `WAL` + `busy_timeout=5000`，缓解读写并发锁冲突。
- **PostgreSQL 生产适配**：兼容层处理 `?` 参数、identity 主键、事务提交和行访问；目标库迁移前后统计一致。
- **并发状态机**：专家任务 `(case_id, expert_id)` 唯一；任务提交、进入终审和终审签署均使用带旧状态条件的原子 `UPDATE` 与 `rowcount` 校验，避免双提交或矛盾终审。
- **reviewer 字段裁剪**：案卷列表和详情对 reviewer 移除终审决定、终审意见及标签，已完成案卷的 `status` 统一为 `completed`；只保留本人任务与可见预审证据。
- **解析与出网防护**：UTF-16/UTF-32 XML 实体声明同样拒绝；RTF 解析超时直接报错；Milvus 公网 URI 未经授权不连接。
- **案卷关联保护**：历史课题一旦被评审案卷引用，删除请求返回 409；终审签署前显示不可覆盖确认，管理员代提交在任务和终审意见中标记。
- **长文档与范围**：`MAX_CONTENT_CHARS` 默认50万字，仍保留容量安全上限；按章节分块建立索引，超过上限明确提示未纳入范围。材料质量显示提取字数、物理页数、OCR页数、处理进度和不完整提示；complete只表示未检测到页数/字数限制或少字/低置信页面，不是图片、表格、签章的真实性或完整性证明。

前端健壮性（经 `tsc --noEmit` + 构建 + 跨路由冒烟验证，无控制台错误）：

- **请求超时**：`api.ts` 的 `request()` 加 `AbortController`（默认 100s，高于后端 90s LLM 预算并留出网络余量），后端卡死时 UI 不再永久挂起，提示“请求超时”；`fetch` 网络异常统一提示“网络错误，无法连接到服务器”。SSE 流式接口不设硬超时（长连接），仅对建连失败做友好提示。
- **ErrorBoundary**：路由外层包裹 `components/ErrorBoundary.tsx`，单页渲染崩溃时显示兜底卡片（重试 / 返回问答），不再整站白屏；按 `pathname` 自动重置。

## 12. 当前边界与下一步

**边界**

- 默认只监听 `127.0.0.1`；内网其他机器访问设 `HOST=0.0.0.0` 前，应先配置强口令（`SEED_DEMO_USERS` + `DEMO_USER_PASSWORD`）与防火墙。已有账号密码登录与四角色权限矩阵，SSO/OIDC 待接。
- 当前使用 Uvicorn 开发模式；生产部署请配置多 worker、Nginx、HTTPS、日志与进程守护。
- PDF支持可选本地OCR：macOS使用系统Vision（需Xcode命令行工具，首次本地编译）；Linux需本地Tesseract及chi_sim、eng语言包和Poppler。没有引擎时保留旧文本并提示失败，不下载模型、不调用云OCR。表格关系、图片和签章仍需人工核对。
- 检索支持 NumPy、pgvector、Milvus 三种存储；生产规模建议 pgvector，达到百万级向量、高并发或多租户后再切 Milvus。混合检索先取向量候选，再在应用层加词面/章节权重和二次排序；嵌入模型尚未全面本地化，公网端点需显式授权。
- 3D 图表依赖 WebGL；无 WebGL 自动降级 2D。
- 已做路由级 code splitting：首屏 JS 约 423KB；3D 趋势页按需加载约 1.66MB（ECharts GL 占比较大）。
- 预审为规则 + 可选千问，不替代专家评审；查重结果需人工复核。
- 政策库当前只有两部公开公文（科技部调查处理规则、江苏项目信用办法），覆盖面有限；条款级比对只给“可能相关条款”，**版本时效（生效/失效/被替代）尚未建模**（`rag/schemas.py` 的 `PolicyMeta` 字段已冻结、存储未启用），引用前须人工核对适用版本。
- 专家匹配目前是原型：示例专家为合成数据；真实专家库、回避关系和负载数据需接入现有系统或 CSV 授权导入。
- 正式研究报告、省厅试点验证报告、论文、软著尚未提交；`交付材料/` 中是初稿/模板，不能当作已验收成果。
- 演示文献为合成数据，不能用于真实研究结论。

**建议下一步**

1. 配置真实 Qwen（内网优先），用 20–30 份真实本子做评测集，校准检索阈值和预审口径。
2. 嵌入模型本地化（bge-m3 落内网）+ 增加 Reranker；先用 pgvector，达到百万级向量后再评估 Milvus。
3. 导入真实政策库（含生效/失效日期），启用条款级合规审查。
4. 接入现有科技管理系统：只读 API/视图、SSO、预审任务回写。
5. 生产化：OCR、权限、审计、加密、等保、模型服务监控。

专家单位回避只统一排版空白、全半角字符及括号，保留英文词间空格与括号内容；不推断简称、别名或隶属关系。页面和 Markdown 导出均保留双方原名、命中依据及缺失申报信息警告。当前回归包含 292 个测试函数，参数化展开为 352 个用例。

生成来源 API 契约：`/api/chat` 和 `/api/review` 返回增量字段 `generation`（`provider`、`label`、`model`、`status`）；SSE 在首段正文之前发 `generation` 事件，`done` 带最终来源。`status` 为 `complete` / `fallback` / `interrupted`。保留旧 `mode="qwen"` 表示模型路径以兼容客户端，不以它判断实际供应商；来源快照不含密钥或接口地址。流未收到 `done` 即结束按中断处理。

问答请求上限为问题 4000 字、历史 12 条且总计 12000 字，公开请求体硬上限 64KB；`/api/health` 与 SSE 的模型元数据只含 `configured/provider/label/model`，不返回内网端点和密钥。项目评审归档保存来源文档名快照，来源删除后仍能列出与读取；接口重算归档正文 SHA256 并返回 `verified/mismatch/unrecorded`，文档中心对不一致归档显示校验失败。

智能问答输入框上方可选择模型和推理强度，每组单选。系统默认沿用现有配置，离线摘录不调用模型；额外模型仅使用对应供应商自身密钥和官方端点，受公网出口门禁控制。DeepSeek 与受支持的千问模型提供关闭思考、低、高、最高；不支持的模型只提供系统默认。设置只影响下一条问答，生成中锁定，切页保留、退出登录或刷新重置；预审和趋势仍用后台配置。高强度可能增加等待和用量。`/api/chat` 与 `/api/chat/stream` 接受可选 `model` 和 `strength`（省略兼容旧客户端），后端校验白名单，来源快照包含实际强度。

所有受保护路由共享同一个单页工作区外壳。左侧导航固定为智能问答、历史课题、项目预审、查重匹配、知识图谱、文献趋势、文档中心、用户管理，并按角色权限过滤；导航名称使用加粗字体。左上角显示完整系统名称且不显示字标图标，顶栏不显示主题和简约模式入口。`/welcome` 是纯总览，只显示当前历史课题与资料指标；工作台顶部统一选择历史课题或单独申报书，切换时同步问答范围并清空与新资料无关的旧回答和证据；历史课题没有当前申请书时预审与查重不可运行。全局资料选择器只在欢迎页、项目预审、查重匹配和申报流程显示；智能问答、文档中心、知识图谱、文献趋势、项目评审、专家审核、专家库和用户管理使用各自任务、范围或目录入口。预审、匹配、趋势、历史课题与用户管理使用统一 `WorkDeck`；历史课题按七步、预审按五步、查重匹配按五步（viewer材料查重三步）、趋势按四步、管理按三步在工作面内切换。文档刷新不会清空当前预审或查重结果，只有当前文档真正变化时重置。常规内容不得把页面撑出视口，长列表在页内翻项；聊天消息、证据、文档正文和图谱等只在固定窗格内滚动。知识图谱宽屏为三栏，≤1050px 或高度≤720px 切为三个分区，720×450 必须保留可操作画布；文档中心固定左目录右书页。政策或文献不会覆盖当前申报书。手机任务态压缩必要的历史课题上下文；≤900px 或高度≤800px 把章节栏转为网格。

预审“边界与导出”按工作面实际宽度和窗口高度切换双栏/单栏，窄屏正文保留有效阅读高度，长内容只在工作面内滚动；Markdown与打印入口均可到达。

### 材料阅读与知识产权保护

管理人员在文档中心打开材料，点击正文旁的“阅读权限”，指定归属账号、额外阅读账号及是否对所有登录账号公开。新上传材料默认受控，归属上传账号；既有真实材料不猜测归属，未公开、未额外授权且不属于本人专家任务时，仅 manager/admin 可读。这是保护旧材料的安全默认，管理人员核实后再显式分配。合成演示本子和已明确公开的政策/文献默认共享，管理人员仍可收紧。将材料标为文献或政策本身不会自动公开上传内容。

申报账号可在“项目预审”和“材料查重”检查归属本人、可读且正文有效的申报材料（proposal/other）。公开或额外获准阅读并不自动赋予viewer检查权。独立查重走 `POST /api/duplicate/check`，只返回查重信息与免责声明，不返回专家候选或回避画像；`/api/tool/check` 和 `/api/experts` 对viewer继续返回403。受委托专家自动获得本人任务申报书的阅读权，其他比对材料需要额外授权。manager/admin 保留全库核验权，阅读与权限变更记录在数据库。受控材料继续参与内部查重；无阅读权的结果只显示本材料片段、相似度及匿名来源，不返回对方题名、ID、片段或原文链接。相似不等于抄袭，仍需人工复核。

权限由后端统一约束文档列表/正文、问答与SSE引用、关键词图谱、关联文献趋势、卷宗材料、预审、查重和专家归档读取。归档原件与签名保持不变；受限读取时生成明确标识的副本并单独计算副本哈希，旧模型报告的叙述没有安全快照时不直接交给受限账号。已送达客户端的内容不能追溯收回；撤销授权对后续请求生效。

升级为新增 `document_access`、`document_access_events` 两张表，SQLite/PostgreSQL 启动时幂等创建；不改既有文档和签名归档，也不按文档名、正文单位或既有登录账号自动推断归属。旧 SQLite 源库缺少新表时迁移跳过这些表，目标材料仍采用同样的安全默认。备份时包含新表，迁移工具一并复制已有权限与访问记录。部署时整体更新前后端，不能混跑仍允许全库读取的旧后端。当前仍是四角色原型，不自动映射单位或SSO组织权限。

申报账号的“材料查重”沿用 `/match` 路由，通过 `visibleWorkspaceViews` 按能力统一生成导航名称，仅包含“运行查重 / 查重结果 / 检查边界”三步，支持导出匿名查重报告。viewer即使尚无本人材料也能找到入口，此时运行按钮禁用，并提示联系管理人员设置材料归属；不静默切换到其他人的材料。reviewer/manager/admin继续使用五步“查重匹配”，专家库与匹配权限不变。

### 本地材料批量处理
