# 科研诚信驱动的自然资源科研全周期智慧治理与大模型协同关键技术研究
## 研究报告（初稿）

> 本报告为课题首期原型阶段的研究报告初稿，包含本地验证结果和合成演示数据，尚未经过省厅试点、专家评审和验收，不能作为正式结题报告使用。

---

## 摘要

针对自然资源科研管理中形式审查耗时、语义查重能力不足、政策条款掌握不一致、专家遴选主观、历史数据难追溯等问题，本课题研究“科研诚信驱动的科研全周期智慧治理与大模型协同”技术体系。首期工作完成了一个可运行的原型系统：以 FastAPI + React 前后端分离，接入 Qwen 兼容模型，构建文档解析、结构分块、检索增强问答、本子预审、语义查重、专家画像匹配和多年文献趋势分析能力。原型在本地验证中跑通了“上传本子 → 查重 → 专家匹配 → 结果导出”的一体化链路，并对重复文档识别、专家回避/负载约束、引用溯源等关键点进行了测试。报告同时给出与申请书研究内容/考核指标的差距和下一阶段工作。

**关键词**：科研诚信；自然资源；大模型；检索增强生成；语义查重；专家匹配；科研全周期治理

---

## 1. 研究背景与目标

### 1.1 背景

国家持续深化科研诚信体系建设，推进人工智能赋能政务数字化治理。江苏省自然资源厅已建成科技管理系统，实现科技项目、科研课题、专家管理的线上流转，但尚未融入智能化审核、诚信风险管控和成果智能赋能能力。现有管理存在：

- 形式审查依赖人工，耗时且标准不一致；
- 字符级查重难以识别改写、跨语言、跨年度重复；
- 政策条款多、版本多，人工掌握成本高；
- 专家遴选主观，回避关系和评审负载难查全；
- 历史项目、成果、专家数据分散，难以形成“历史底数”。

### 1.2 目标

围绕“科研诚信 + 科研全周期 + 大模型协同”，构建外挂式智能评审辅助能力：

1. 文档可解析、可检索、可引用；
2. 申报书可做形式、诚信、查重、合规预审；
3. 查重与专家匹配形成一体化工具；
4. 多年文献趋势可分析；
5. 为后续知识图谱、风险模型、Agent 协同和系统集成留出接口。

## 3. 技术路线与系统架构

### 3.1 三层架构

**数据资源层**：多源文档（申报书、政策、文献）接入，解析、清洗、分块、元数据、权限；首期使用 SQLite + 本地文件，真实数据接入待完成。

**技术攻关层**：

- 文档结构感知分块；
- TF-IDF + 关键词/章节加权的检索；
- RAG 问答与引用；
- 规则预审 + 可选千问结构化预审；
- 段落级查重；
- 专家画像匹配（回避/负载约束 + 语义/关键词/学科评分）；
- 文献趋势统计与摘要。

**应用验证层**：React 工作台，含问答、文献趋势、查重匹配、本子预审、文档库；首期为本地验证，未进入省厅试点。

### 3.2 外挂式集成

系统不修改现有科技管理系统，设计三种外挂方式：

1. 入口外挂：iframe/微前端 + SSO；
2. 服务外挂：现有系统调用查重/合规/专家匹配 API；
3. 数据外挂：只读 API/视图/文件导出同步数据。

首期完成独立工作台和 API，未与现有系统联调。

## 4. 关键技术

### 4.1 文档解析与结构分块

- DOCX：Word XML 解析段落和表格，保留章节文本；图片不进入文本；表格转“单元格 | 单元格”；
- PDF：`pdftotext -layout` 按页提取，保留页码；
- 分块：按章节标题、段落、句边界切分，块约 700 字、重叠 100 字并对齐句边界；
- 引用：PDF 到页码，DOCX 到章节；回答中的 `[n]` 对应右侧证据。

### 4.2 RAG 问答

流程：查询 → TF-IDF 检索（字符 n-gram + 关键词/章节加权）→ 相关性过滤 → 编号资料 → Qwen 或离线摘录 → 引用展示。

- 配置千问时，严格依据检索资料回答；
- 未配置时，返回原文摘录并明确“离线演示”；
- 资料不足时拒答；
- 当前未使用向量检索和重排，语义召回有限。

### 4.3 语义查重

- 对已入库文档做段落级 TF-IDF 余弦相似度；
- 输出相似文档、最高相似度、本子/比对文档原文片段；
- 阈值：≥0.55 高相似，0.30–0.55 关注；
- 明确“相似不等于抄袭”，需人工复核；
- 当前仅覆盖已入库文档，历史本子/成果库越大越有效。

### 4.4 专家画像匹配

专家字段：姓名、单位、职称、学科、研究方向、代表成果、回避单位、回避人员、在研项目数、是否可评审；不采集性别、年龄。

匹配流程：

1. 提取申报单位/负责人和本子主题词；
2. 硬约束过滤：不可评审、在研≥5、同单位、回避单位/人员；
3. 语义相似度：本子文本 vs 专家画像（字符 n-gram TF-IDF）；
4. 关键词/学科加分；
5. 负载惩罚；
6. 输出相对匹配度、理由、排除原因。

该方法是可解释的启发式原型，绝对分数需用真实抽取结果校准。

### 4.5 文献趋势

- 按主题词筛选文献（标题/关键词/摘要命中 + 字面相似）；
- 年度发文量、主题热度、年度高频主题、代表文献；
- 3D 柱状图/主题矩阵 + 2D 切换；
- 规则摘要；配置千问时生成趋势研判；
- 当前演示文献为合成数据。

### 4.6 本子预审

- 形式完整性：章节、参考文献、文档长度；
- 诚信与规范：科研诚信、数据安全、伦理、知识产权表述；
- 查重：段落相似度；
- 政策合规：未接政策库时仅作通用提示；
- 可选千问 JSON 预审；
- 输出风险等级、检查项、问题清单、免责声明。

## 5. 系统实现

- 后端：FastAPI + Uvicorn + Pydantic；SQLite；`rag/` 模块化服务；
- 前端：React 19 + TypeScript + Vite + React Router；ECharts/ECharts GL；Framer Motion；
- 模型：Qwen/OpenAI 兼容接口；未配置时离线；
- 部署：本地 Uvicorn；生产建议 Gunicorn/Uvicorn 多 worker + Nginx + HTTPS；
- 安全：默认监听 127.0.0.1；无 SSO/RBAC；生产需接厅统一身份、权限、审计、加密。

## 7. 与申请书要求的差距

1. **知识图谱未建**：目前只有关系型元数据，没有实体关系图谱；
2. **向量检索未上**：TF-IDF 语义能力有限；
3. **智能受理/政策条款合规未完成**：缺表单校验、政策库、版本时效；
4. **风险模型与 Agent 未做**：缺失信特征模型、三类 Agent 协同；
5. **成果转化未做**：缺多模态成果归集与业务场景匹配；
6. **未接真实系统/真实数据**：无 SSO、只读接口、真实专家/历史本子；
7. **未开展省厅试点**：本地验证不等于正式试点；
8. **正式成果未提交**：研究报告/试点报告/论文/软著均为初稿或材料准备。

## 9. 结论

首期原型证明了“文档解析—RAG 问答—查重—专家匹配—预审—趋势”技术链路可行，并完成了考核指标中一体化工具的核心功能。
